# トラブルシューティング

まずパネルの **接続して更新 / Connect and refresh** を実行し、表示される案内に従ってください。

| 状況                                         | 対処                                                                                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| セットアップできない、制限モードと表示される | フォルダの内容を確認して VS Code のワークスペース信頼を設定する                                                                      |
| `AUTH_REQUIRED`、サインインを求められる      | 専用ウィンドウで職場または学校アカウントにサインインし、追加認証を完了する                                                           |
| 個人アカウントの Copilot が開く              | サインイン画面で、エージェントを利用できる職場または学校アカウントに切り替える                                                       |
| エージェントがない、一部しか表示されない     | Microsoft 365 側で同じアカウントから対象を開けることを確認し、接続して更新する                                                       |
| `WORKSPACE_APPROVAL_REQUIRED`                | 利用するエージェントを確認して承認・保存する                                                                                         |
| `BROWSER_START_FAILED`                       | Edge または Chrome のインストール先とパネルのブラウザー設定を確認する                                                                |
| `BROWSER_PROFILE_LOCKED`                     | 同じ専用プロファイルを使用している処理が終了するのを待ち、接続し直す。通常使用中のブラウザープロファイルは指定しない                 |
| `UI_CHANGED`                                 | Microsoft 365 の画面が想定と異なる。拡張機能を更新し、改善しなければ診断情報と再現手順を報告する                                     |
| `RESPONSE_TIMEOUT`                           | 回答が Microsoft 365 側で継続している可能性がある。元の会話を確認し、必要に応じて設定ガイドの待ち時間を調整する                      |
| `SUBMIT_STATE_UNKNOWN`                       | 送信済みの可能性がある。重複送信を避けるため、元の会話を確認してから再送を判断する                                                   |
| ファイルが保存されない                       | ダウンロード有効化、許可ホスト、サイズ上限を確認する。生成したエージェント側がダウンロード可能なファイルを提供していることも確認する |
| 更新後も古い動作が残る                       | VS Code を再読み込みし、接続して更新する                                                                                             |
| 外部クライアントにツールが出ない             | 連携を有効にして保存し、そのクライアントを再起動する。クライアント側の MCP 設定と利用許可も確認する                                  |

質問を送った後で接続が切れた場合、AgentPickLink はその質問を自動再送しません。復旧後の再送は、元の会話と処理結果を確認してから行ってください。

## 添付ファイルが保存済みなのに開けない場合

v0.1.2 以前では、PDF が `APL_downloads` 内に `attachment-1` のような拡張子なしの名前で保存される場合があります。MIME が `application/pdf`、先頭が `%PDF-1.3` などなら、拡張子がないことだけで別形式や破損とは判断できません。原本を残し、`.pdf` を付けたコピーを PDF 対応アプリで開いてください。

v0.1.3 では、HTTP／同一 origin の Blob の MIME、形式の識別情報、選択した添付のファイル名から欠けた拡張子を補います。既存ファイルの名前やバイト列は自動変更しません。更新後は VS Code を再読み込みし、外部 AI クライアントの MCP 接続も再起動してください。

保存名は M365 の応答ヘッダー／ブラウザーが提供する具体的なファイル名を優先します。それが `attachment`・`download`・UUID 等なら、選択したファイルカードやリンクに表示された名前、取得先 URL のファイル名を使います。元の名前が取得できない場合だけ代替名になります。日本語・空白・丸数字などは保持しますが、パス要素や OS で使えない文字は取り除き、同名の別ファイルには `-2` 等を付けます。修正前に保存したファイルは自動で改名しません。

| 形式                                           | 拡張子・MIME を補う情報                                                                             |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| PDF、PNG/JPEG/GIF/WebP/TIFF/BMP/ICO、AVIF/HEIC | MIME、元の名前、ファイルの識別情報                                                                  |
| DOCX/XLSX/PPTX、マクロ付き形式・テンプレート   | MIME、元の名前、ZIP 内の小さな形式メタデータ。単に ZIP の先頭が一致しただけでは Office と判断しない |
| DOC/XLS/PPT                                    | MIME、元の名前、OLE コンテナー内のディレクトリ情報                                                  |
| ODT/ODS/ODP、EPUB                              | MIME、元の名前、ZIP 内の mimetype                                                                   |
| WAV/MP3/FLAC/OGG、MP4/M4A/MOV/WebM/AVI         | MIME、元の名前、対応する識別情報                                                                    |
| ZIP/GZIP/TAR/7z/RAR、RTF                       | MIME、元の名前、対応する識別情報                                                                    |
| CSV/TSV/TXT、JSON/XML、Markdown/YAML、HTML/SVG | MIME または元の名前。テキスト内容だけからは推測しない                                               |

識別情報は形式の手掛かりであり、文書の正しさや再生可能性の検証ではありません。暗号化・形式不明・判別が曖昧なファイルは、内容から拡張子を決めません。ZIP64 等の未対応コンテナーや走査上限を超えるものは、元の MIME／名前を使用し、それもなければ ZIP 等の汎用形式のまま保存します。既存の拡張子や README 等の意図的な拡張子なしテキストも保持します。原本の形式が分からない場合に、見た目だけで拡張子を書き換えないでください。

AI クライアントは返却された `localPath` または `resource_link` から実ファイルを読みます。MCP の `resources/read` が返す `blob` は base64 なので、対応ツールに渡す前に元のバイト列に復号します。AgentPickLink は文書リーダー、表計算エンジン、描画ツール、メディアプレイヤーを呼び出し元環境に提供しません。対応ツールがない場合とファイルの破損は別の問題です。PDF の本文抽出だけではフォントや表示の正しさは確認できないため、抽出結果とページ描画の確認範囲を分けて報告してください。

## SharePoint / OneDrive のファイルが保存されない場合

v0.1.2 では、共有リンクの認識とサインイン転送後のファイル取得に加え、添付リンクが順に表示される場合の取得を改善しています。まず拡張機能のバージョンを確認し、更新後は VS Code と外部クライアントの MCP 接続を再読み込みしてください。

対象ファイルを同じ Microsoft 365 アカウントで開けること、パネルのファイル保存が有効なこと、取得先が許可ホストに含まれることを確認してください。ファイルへのアクセス権限やテナント側の制限は、拡張機能の更新では変更されません。

## Codex の設定更新について

v0.1.2 では、無関係な TOML 設定を保持し、変更前のバックアップを保存します。保存に失敗した場合は、設定ファイルの構文、権限、他のアプリによる同時編集を確認してください。旧版ですでに失われた設定は自動復元できないため、以前のバックアップがある場合は内容を確認して復元してください。

## 不具合の報告

公開リポジトリの Issues に、バージョン、OS、VS Code とブラウザーのバージョン、再現手順、エラーコードを記載してください。パネルの **ログを開く / Open logs**、**診断をコピー / Copy diagnostics** を利用できますが、共有前に内容を確認してください。

質問・回答本文、生成ファイル、エージェントの説明、組織固有の URL、アカウント情報、Cookie、トークン、ブラウザープロファイルを報告に添付しないでください。脆弱性の疑いがある場合は [セキュリティ方針](SECURITY.md) に従ってください。
